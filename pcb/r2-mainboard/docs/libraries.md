# Project-local symbols and footprints — what was made here, and how to check it

Everything in `r2.kicad_sym` and `r2.pretty/` was **created for R2** because it did not exist in
KiCad's stock libraries or in the `pcb_common` submodule that came with Glider. This file is the
audit list: what each thing is, what it was derived from, which script emits it, and what was
actually checked.

**`pcb_common` has never been modified.** It is a submodule shared with R1; every addition went into
the project-local `r2` libraries instead, so `git -C pcb/pcb_common status` should always be clean.
If it is not, something has gone wrong.

Written 2026-08-31, at the owner's request, before rehoming the libraries.

---

## 1. How to re-derive any of these

Every entry is generated by a script in `tools/`, not drawn by hand. That is deliberate: a generated
footprint can be re-emitted and diffed against the datasheet numbers, and most of the generators
assert their own geometry. To check one, read the script's header — it names the drawing and the
page — then re-run it and confirm the file is unchanged.

## 4. The three added 2026-08-30/31, in more detail

These are the newest and the least reviewed, so they are worth checking first.

### 4.1 `TPS2553DBV` symbol

Pin assignment is straight off the datasheet's **Pin Functions** table (SOT-23 column), which lists
two variants — the `TPS2552` has `EN` active *low* on pin 3 and the **`TPS2553` has `EN` active
high**. We fit the `TPS2553`, so `EN` is active high, which is what lets the SoM's `X_USB1_DRVVBUS`
drive it directly with no inverter.

| Pin | Name | Type |
| ---: | --- | --- |
| 1 | `IN` | power_in |
| 2 | `GND` | power_in |
| 3 | `EN` | input — **active high** |
| 4 | `~{FAULT}` | open_collector |
| 5 | `ILIM` | passive |
| 6 | `OUT` | power_out |

**Footprint is KiCad's stock `Package_TO_SOT_SMD:SOT-23-6`** — nothing new was drawn for it.

⚠ **What to check:** that pin 3 really is `EN` and not `EN` on the part you order. The `-1` suffix is
the latch-off version and the `TPS2552` is the active-low sibling; both are the same package with the
same pin *numbers*. We specify `TPS2553DBVR`, LCSC `C55266`.

### 4.2 The two `_Mirrored` FPC footprints

These are **not new land patterns**. Each is its parent with the *numbered pads mirrored in X* and
the pin-1 silkscreen tick moved; the body, the courtyard and the mechanical pads are untouched.

Both parts happen to carry **two symmetric mechanical pads** (±2.75 mm and ±11.4 mm), so the land
pattern is geometrically identical to the original — the same physical connector solders down in the
same orientation, and only *which net reaches which contact* changes.

They exist because the panel's two tails arrive with their pin 1 at opposite ends, and neither stock
footprint matched: `HC-FPC-05-09-8RLTAG` numbers from +x, `Omron XF2M-4015-1A` from −x. Full
reasoning and the bench measurement in `epd-port.md` §9.6.

⚠ **What to check:** `gen_mirrored_fpc.py` asserts, on every run, that pad 1 lands on pad *N*'s old
x and that the mechanical pads did not move. Re-run it and confirm the files are byte-identical. Then
check the *silkscreen pin-1 marker* has moved with the pads — it is the only thing an assembler sees.

This is also the convention `pcb_common` already uses: it ships **eight** `_Mirrored` variants
(`Xunpu_FPC-05F-8PH20_…`, `Hirose_FH12-…`) for exactly this reason. We put ours in `r2.pretty`
instead of adding to the submodule.

## 5. Not ours

For completeness, so the audit does not chase them:

- **`SAMTEC_BTH-060-X-X-D-A-K.kicad_mod`** in `datasheets/SoM Phycore AM62x/BTH-060-01-L-D-A-K-TR/`
  is Samtec's own download. It is *not* what the board uses — `gen_som_footprint.py` emits the two
  half-connectors with the module's pad names instead (`som.md` §10.2).
- Everything under `pcb_common/` came with Glider and is shared with R1.
- `Connector_Generic_MountingPin:Conn_01x40_MountingPin`, embedded in `epd.kicad_sch`, is KiCad's own
  symbol — but this machine has no KiCad symbol libraries installed, so `patch_j6_40pin.py` generated
  it by transforming the 50-pin variant already embedded in that sheet (drop pins 41–50, shift the
  rest by 12.7 mm). It is why ERC reports one `lib_symbol_mismatch` for it. **If you install KiCad's
  stock libraries, replace the embedded copy with the real one** and that warning goes away.
